# Firework Store

Интернет-магазин пиротехники на Next.js (App Router). Каталог и карточки
товаров рендерятся на сервере; корзина и оформление заказа — единственные
клиентские части приложения.

## Установка и запуск

```bash
npm install
npm run dev
```

Приложение будет доступно на [http://localhost:3000](http://localhost:3000).

## Переменные окружения

Создайте `.env.local` в корне проекта (файл уже в `.gitignore`, не коммитьте
его):

```env
TELEGRAM_BOT_TOKEN=your_bot_token_here
TELEGRAM_CHAT_ID=your_chat_id_here
```

**Важно:** это серверные переменные — без префикса `NEXT_PUBLIC_*`. Такой
префикс означает, что значение попадёт в клиентский бандл и будет видно
любому посетителю сайта; именно так токен бота был скомпрометирован в
истории проекта (см. `SECURITY_INCIDENT.md`). Токен читается только в
`lib/orders/telegram.ts` — серверном модуле, помеченном `import 'server-only'`,
который физически не может попасть в код, отправляемый в браузер.

Без этих переменных сайт продолжает работать: оформление заказа сохраняет
заказ (см. ниже), но честно сообщает, что не удалось уведомить магазин,
вместо того чтобы притворяться успехом.

### Получение токена Telegram-бота

1. Создайте бота через [@BotFather](https://t.me/BotFather) в Telegram.
2. Получите токен бота.
3. Узнайте ID чата, куда будут приходить заказы (например, через
   [@userinfobot](https://t.me/userinfobot)).

## Данные каталога

Товары и категории (`content/products.ts`, `content/categories.ts`) —
детерминированная фикстура (сид фиксирован, одинаковый результат при
каждом запуске сервера — это важно для SSR: без этого сервер и клиент
генерировали бы разные случайные данные и ловили hydration-ошибку).

Всё обращение к каталогу идёт через `lib/catalogue.ts` — единственную
точку входа для `getProducts`, `getProductBySlug`, `getCategories` и т.д.
Компоненты и бизнес-логика не импортируют `content/*` напрямую и не знают,
что источник данных — фикстура, а не 1С. Когда появится реальная
интеграция с 1С, замене подлежит только `lib/catalogue.ts` (и, при
необходимости, добавление настоящего эндпоинта уведомлений в
`lib/orders/store.ts`, который сейчас использует файловое хранилище
заказов в `data/orders/`) — остальной код менять не придётся.

## Технологии

- Next.js 16 (App Router, React Server Components, Server Actions)
- React 19
- TypeScript
- Tailwind CSS v4
- React Hook Form + Zod (валидация оформления заказа — одни и те же
  правила проверяются на клиенте для UX и на сервере как гарантия)
- Vitest + React Testing Library

## Docker

```bash
docker build -t firework-store .
docker run -p 3000:3000 --env-file .env.local firework-store
```

Собирает `output: 'standalone'` — минимальный самодостаточный сервер без
лишних файлов репозитория и неиспользуемых зависимостей в образе.
